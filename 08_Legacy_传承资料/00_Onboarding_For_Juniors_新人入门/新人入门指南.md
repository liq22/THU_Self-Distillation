# 新人入门指南（给师弟妹）

> 敏感原件与大体积资产只写私有指针, 规则见 [[处理规范_脱敏与可见性]]。

## 适合谁读

刚进组（或刚确定方向）的清华机械系 / 相关方向低年级博士生，想用一两周内把环境、文献、流程理顺、尽快进入可推进状态。

## 读完能做什么

- 知道第一周、第一个月各该把哪几件事落地，不至于空转。
- 知道这个 vault 里哪些页是"必读入口"，遇到具体环节去哪里查。
- 避开"不记实验条件、只读论文不建索引、过早冲大问题"几个最常见的新手坑。

## 前置条件

- 已拿到课题组常用账号（git / 文献库 / 计算资源），能访问本 vault。
- 已和导师或师兄师姐约过一次方向沟通。

## 第一周应该完成什么

- [ ] 了解课题组研究方向（读 1–2 篇组内代表作，弄清大方向与自己的小切口）
- [ ] 配置常用账号和工具（git、文献管理、计算环境、本 vault 的读写权限）
- [ ] 读完核心文献清单（10–20 篇，先建索引卡再细读）
- [ ] 复现一个最小实验或案例（哪怕只跑通一条 baseline，建立可运行环境）
- [ ] 和导师/师兄师姐对齐第一个月目标（写出一句可验证的研究问题）

## 第一个月建议推进

- [ ] 把研究方向拆成 2–3 个可验证的小问题，挑一个先做。
- [ ] 建立"私有材料夹 + 公开 Markdown 索引"的双层结构：原件本地、公开仓只记类型与经验（见 [[处理规范_摄入与整理流程]]）。
- [ ] 每篇重要文献建一页 paper-note 索引卡（问题 / 方法 / 与我相关 / 可复用），不要只存 PDF。
- [ ] 每周写一条简短周记：做了什么、卡在哪、下周试什么。

## 最容易踩的坑

| 坑 | 后果 | 建议 |
|---|---|---|
| 不记录实验条件 | 结果无法复现 | 每次实验都写实验记录 |
| 只读论文不建索引 | 知识碎片化 | 每篇重要文献写一页笔记 |
| 过早追求大问题 | 推进缓慢 | 先找可验证的小问题 |
| 原件直接进公开仓 | 签字 / 学号 / 评审意见泄露 | 公开仓只写类型，原件留私有区 |
| 环境只在自己机器跑通 | 换机器就废 | 关键依赖写成脚本 / 环境文件，能一键重建 |
