## 边界说明

这页是写给人（师弟妹）与 agent 共读的**摄入与整理总规范**：一条材料从进 Inbox 到沉淀成 skill/dashboard，经过哪些固定步骤、哪些层、哪些不变量、哪些保护。

它和同系列规范页**分工不重叠**：

- **本页**管**摄入与整理的动作链**：6 步增量节奏 + 五层处理流水线 + 源不变性 + 围栏保护。
- [[处理规范_命名与模板]] 管**怎么命名、用哪个 frontmatter 字段**（命名约定、canonical frontmatter、模板中心）。
- [[处理规范_脱敏与可见性]] 管**敏感内容怎么处理**（学号/隐私/路径脱敏、private 区规则、公开前检查）。

敏感件（签字扫描、身份证、审稿意见原件、含学号路径）本页只写**规则与边界**，原件落 `98_Private_LOCAL_勿提交/`，公开页只留类型与指针——详细脱敏操作见 [[处理规范_脱敏与可见性]]。

> 术语：raw（原始记录，不改写）/ compiled（整理产物）/ schema（结构化字段）/ skill（可复用能力）/ dashboard（面向人总览）；data plane（执行内容）/ control plane（规则模板）。

## 适合谁读

- 第一次接手本 vault 整理、不知道"一条新材料进来该走哪条链"的师弟妹。
- 任何在本 vault 内运行、需要遵守摄入与保护不变量的 agent。
- 想把外部源仓库（含绝对路径、用户名、机器布局）蒸馏进本 vault 的人/agent。

## 读完能做什么

- 知道 Inbox 里的材料每周按哪 4 条规则分流（移动 / 保留+note / 删除 / 隐私→private）。
- 知道 6 步增量节奏（随手收集 → 每周归档 → 每月复盘 → 项目收尾 → 论文收尾 → 毕业前清理）各做什么。
- 知道一条材料从 raw 走到 dashboard 的固定五层，且 raw 只追加不覆盖。
- 知道 raw/compiled 围栏、`98_Private`（gitignored 原始件）/ `99_Archive`（只读证据快照）的边界。
- 知道整合外部仓库时如何用 COPY-ONLY 不变量（开工前基线 + 收尾重测逐字节比对）证明源未改。
- 知道高风险目录靠 `readonly` / `scope:subtree` / `fix` 三件套降级保护。

## 1. Inbox 摄入规则

Inbox（`00_Inbox_收集箱/`）的设计目标是**降低记录门槛**，不是追求完美分类。任何暂时无法归类的材料先落这里。每周按以下 4 条分流（出处：`00_Inbox_收集箱/README.md`「每周处理规则」）：

| # | 判据 | 动作 | 落点 |
|---|---|---|---|
| 1 | 能明确归属 | 移动到对应顶层目录并补齐元数据 | `02_Research` / `03_Papers` / `04_Thesis` / `06_Thinking` / `07_Feedback` / `08_Legacy` / `09_Admin_Career` 等 |
| 2 | 暂时不确定但重要 | 保留在 Inbox，补一句说明（note） | 仍留 `00_Inbox_收集箱/`，文件内或文件名注明"为什么留着" |
| 3 | 无价值 | 删除 | 不进任何归档 |
| 4 | 涉及隐私 | 移动到**本地 private 目录**，不提交公开仓库 | `98_Private_LOCAL_勿提交/`（gitignored） |

> 规则 4 的"隐私"指：签字扫描、身份证/学号、电话/邮箱、未发表结果、审稿意见、合作者数据、含绝对机器路径的资产指针。这些**绝不进公开 git 树**。具体形态与脱敏操作见 [[处理规范_脱敏与可见性]] 与 [[蒸馏外部源仓库时绝对路径会泄漏进公开页]]。

Inbox 可放内容（出处：`00_Inbox_收集箱/README.md`「可放内容」）：临时想法、会议后随手记录、论文灵感、待分类截图或链接、毕业整理时翻出的旧材料。

## 2. 六步增量整理流

整理不是一次性大扫除，而是固定节奏的增量动作（出处：根 `README.md`「增量整理流程」）：

1. **随手收集**：想法、文件、截图、会议纪要先进入 `00_Inbox_收集箱/`。门槛优先于分类。
2. **每周归档**：把 Inbox 内容按 §1 四条规则移动到对应目录，并补齐元数据（frontmatter）。
3. **每月复盘**：更新 `01_Dashboard_总览/PhD_Timeline.md`、项目状态、论文状态。让仪表盘跟上现实。
4. **每个项目收尾**：补齐项目页、实验记录、失败经验、代码/数据说明。
5. **每篇论文收尾**：补齐手稿、投稿记录、审稿反馈、rebuttal、发表版本与复盘。
6. **毕业前清理**：统一脱敏、确认公开范围、整理传承资料（含快照进 `99_Archive`）。

> 节奏的硬要求：第 6 步是**唯一允许做全仓脱敏**的时机，但脱敏规则在每一步都适用——不要把脱敏全堆到毕业前。

## 3. 五层处理流水线（raw → dashboard）

任何输入从"原始"走到"可用"，都经过固定五层（出处：`LQQL_OS自蒸馏OS方法论.md`「五层处理流水线」）。**这是更深模型，决定一条材料在 vault 里的成熟度**：

| 层 | 名称 | 性质 | 关键不变量 |
|---|---|---|---|
| 1 | **raw** | 原始记录（截图、纪要原文、录音转写、源卡片） | **只追加，不覆盖**（保溯源链） |
| 2 | **compiled** | 整理后产物（蒸馏页、摘要、提炼） | 可改写，但必须指向其 raw 源 |
| 3 | **schema** | 结构化字段（让 agent 可解析的 frontmatter + 分段） | 字段遵循 [[处理规范_命名与模板]] canonical schema |
| 4 | **skill** | 固化成可复用能力（最小完整包：`SKILL.md` + `examples/prompts.md`） | **只有走到这一层才算"学会了"** |
| 5 | **dashboard** | 面向人的总览与待办（`01_Dashboard_总览/`） | 人看的入口，不是 agent 的执行面 |

关键约束（出处：方法论「关键约束」）：

- **raw 只追加不覆盖**——raw 被改写，溯源链立刻断，是一切整理的红线。
- **只有走到 skill 层才算学会了**——compiled/schema 都还是"在整理"，没沉淀成能力。
- 材料稀薄时允许合并 raw→compiled，但**不能跳过 raw**。
- OS 是 control plane（规则/模板/`00_系统说明`/`07_给智能体用`），项目 repo 是 data plane（`06_工作与项目` 执行单元）——执行内容不要塞进 control plane。

## 4. raw/compiled 围栏 + 98_Private / 99_Archive 边界

vault 有两个"原始/不可改"区，规则不同（出处：`A0_毕业整理_snapshot_202606/README.md`「边界说明」+ 方法论「围栏保护」）：

### raw 层（vault 各域内的原始记录）

- **只读追加**：可在 raw 内新增记录，但**不得覆盖/删除既有内容**。
- agent 整理 raw 时只做"摘录 + 指针"，不就地改写；产物落 compiled 层。

### `99_Archive_归档/`（只读证据快照）

- 性质：外部源仓库的**只读快照副本**，仅作可追溯证据（如 `A0_毕业整理_snapshot_202606/`）。
- **请勿在本目录内新增 / 编辑 / 删除文件。** 需要更新时，回到源仓库维护，再重新快照。
- 快照**忠实保留源**（含源里的学号/路径形态）——这是另一套规则；快照若要进公开仓，需单独 sed 脱敏并在 README 注明（出处：[[蒸馏外部源仓库时绝对路径会泄漏进公开页]]「忠实证据快照 ≠ 蒸馏页」）。
- vault 的**正式知识页**在各域（`02_Research` / `03_Papers` / ...），那里才是经深度蒸馏、脱敏、按模板整理后的页面；`99_Archive` 只是它们上游的原始规划素材。

### `98_Private_LOCAL_勿提交/`（gitignored 原始件 / 私有指针区）

- 性质：敏感原件与大体积资产的**私有指针区**，gitignored，不进公开仓。
- 完整绝对机器路径、资产 sha256、学号原件、签字扫描都落这里。
- 公开页只留**可移植相对 token**（如 `LQQL_OS/论文流水线/X/`、`D01_vibench/`），不抄绝对路径（出处：[[蒸馏外部源仓库时绝对路径会泄漏进公开页]]「路径指针要拆成两半」）。

> 区分：`99_Archive` = 忠实证据（可追溯，含敏感形态，进公开需脱敏）；`98_Private` = 私有指针（gitignored，永远不进公开）。两者都是"只读/不进公开"，但服务对象不同。

## 5. 源不变性 COPY-ONLY 不变量

把外部源仓库（如 `/mnt/d/A0_.../A0_毕业整理/`、夸克网盘镜像）蒸馏/导入进本 vault 时，**源原样未动**是硬不变量（出处：`A0_毕业整理_snapshot_202606/README.md`「源不变性」+ [[蒸馏外部源仓库时绝对路径会泄漏进公开页]]「源不变性要基线 + 终检双测」）：

### 开工前：记源基线

```bash
find <src> -type f | wc -l          # 文件数
du -sb <src>                        # 总字节数
# （可选，逐字节校验）对关键子集记录逐文件大小/哈希清单
```

### 整理全程：只复制，不改源

- 所有动作是**复制 / 摘录 / 指针化**，源目录内不得增删改。
- 蒸馏产物落本 vault 各域（compiled 层），源留给快照。

### 收尾：重测逐字节比对

```bash
find <src> -type f | wc -l          # 应 == 基线
du -sb <src>                        # 应 == 基线
# 逐文件大小/哈希 identical 应 == 基线计数，mismatch == 0
```

> 若终测 != 基线，说明**误写了源仓库，需回滚**。这条是 COPY-ONLY 的证明手段，不是可选检查。
>
> 实例：`A0_毕业整理` 基线 131 文件 / 239,899,378 字节；其中 `os_cards`+`manifests`+`scripts` 28 文件逐字节校验 identical=28 / mismatch=0，证明源未改（出处：`A0_毕业整理_snapshot_202606/README.md`「源不变性（COPY-ONLY 不变量）」）。

### 附加：蒸馏后必跑两条 grep（出处：[[蒸馏外部源仓库时绝对路径会泄漏进公开页]]「可执行清单」）

1. **强敏感值**：学号 / 身份证 / 手机 / 邮箱 / token 形态（`sk-`、`ghp_`、`AKIA`、`Bearer`）。
2. **机器路径与用户名**：`/mnt/[a-z]/`、`/home/<user>/`、Windows 盘符、用户名（如 `<user>` / `<user>`）。

命中机器路径 → 建/更新 `98_Private_LOCAL_勿提交/资产指针索引_<date>.md`，公开页 sed 成相对 token（specific-first，保留尾部去前缀）。路径不像学号那样触发敏感直觉，**必须靠验证 grep 兜底，不能只靠 prompt**。

## 6. readonly / scope:subtree / fix 保护三件套（高风险目录）

对不可再生资产（raw 记录、归档快照、私有指针、敏感件）用写策略围栏保护（出处：`LQQL_OS自蒸馏OS方法论.md`「fix 机制 + 高风险保护」+ [[蒸馏外部源仓库时绝对路径会泄漏进公开页]]「父级方法论在 fix:true / readonly / subtree 围栏内」）：

| 件 | 作用 | 典型落点 |
|---|---|---|
| `write_policy: readonly` | 只读，禁止改写 | raw 层、`99_Archive`、`98_Private` 指针索引 |
| `scope: subtree` | 限定 agent 作用范围到子树，不外溢 | 一次只动一个项目/一个子树，不跨域 |
| `fix` 机制 | 命中风险（raw、fix、readonly、高风险或高歧义场景）时**降级到 hold / recommendation**，不直接改 | 围栏触发即停下、报告、等授权 |

> 这三件套对应全局规则里的"raw、fix、readonly、高风险或高歧义场景降级"。命中围栏时 agent **不发明例外**，降级为 hold / recommendation；越界写入（如把 OS 级方法论写进被围栏的 `09_智能体开发`）需用户显式授权。

## 7. frontmatter 调和：以 canonical 规范为准

本 vault 存在两套 frontmatter 写法，本规范**以根 `README.md`（规范 #1，canonical）+ Template_Legacy_Guide 为准**，调和 ingest-workflow（`11_Skills/.../workflows/01_ingest_and_link.md`）的分歧字段：

| 字段 | canonical（规范 #1，本规范采用） | ingest-workflow 旧字段 | 调和动作 |
|---|---|---|---|
| 时间 | `created` + `updated`（ISO `2026-07-09`） | `date` | ingest 的 `date` → 拆成 `created`/`updated`；细节命名见 [[处理规范_命名与模板]] |
| 可见性 | `visibility: public\|internal\|private` | `privacy: private` | `privacy` → `visibility`；统一三档枚举 |
| 类型 | `type`（`legacy-guide` / `note` / `lesson` / `project` / ...） | `type` | 一致；legacy 指南用 `legacy-guide` |
| 状态 | `status: seed\|growing\|stable\|archived` | `status` | 一致 |
| 关联 | `related: []`（双链数组） | `source` / `project` / `paper` / `people`（散字段） | 关联对象统一进 `related`；`source` 形态（raw/meeting/email/...）保留为正文 provenance 块或 `source_kind`，不与 `related` 混 |
| 受众 | `audience`（本规范新增 `[junior, agent]`） | — | 传承指南强制带 audience |
| 标签 | `tags: []` | `tags` | 一致 |
| 标题 | `title` | — | 必填 |

> ingest-workflow 的「Normalized note sections」（摘要 / 事实 / 我的理解 / 关联项目论文 / 后续动作 / 相关笔记）是**信息类笔记**的推荐正文结构；**legacy-guide 类**用 Template_Legacy_Guide 结构（适合谁读 / 读完能做什么 / 前置条件 / 标准流程 / 常见坑 / 检查清单 / 示例 / 延伸阅读）。两类页面的 frontmatter 都用 canonical schema，分歧只发生在正文骨架，不在字段层。
>
> 后续散落副本（含 ingest-workflow）若与本节冲突，回指本页并迁到 canonical 命名。

## 常见坑

| 坑 | 表现 | 解决办法 |
|---|---|---|
| raw 被顺手改写 | agent/人整理时直接改 raw 原文，溯源链断 | raw 层配 `readonly`；只摘录+指针，产物落 compiled |
| 大资产偷偷进 git | 视频/数据集/venv/PDF 全文塞进公开仓，体积爆炸 | 大资产（>几十 MB）只写 `98_Private` 指针，不内联 |
| 绝对路径泄漏进公开页 | 蒸馏页原样抄了 `/mnt/...`、`/home/<user>/` | 公开页只留相对 token，完整路径进私有指针；蒸馏后必跑 grep 兜底 |
| 把分主题当顶层组织方式 | 顶层按主题分，待办/归档污染知识树 | 先按对象分（00 系统 / 01 待办 / 05 知识 / 06 项目 / 07 agent / 99 归档），主题留叶子 |
| 源不变性只信 prompt 不重测 | 没记基线/没终检，事后无法证明源未改 | 开工前 `find/du` 基线 + 收尾重测逐字节比对 |
| 围栏触发后发明例外 | agent 命中 readonly/fix 仍强行写入 | 降级 hold / recommendation，越界需显式授权 |
| 脱敏全堆到毕业前 | 学号/路径散在公开页，到第 6 步才批量处理 | 每步增量脱敏，毕业前只做全仓复验 |
| frontmatter 两套混用 | `date` 与 `created/updated`、`privacy` 与 `visibility` 并存 | 统一用 canonical（`created/updated` + `visibility` + `related`） |

## 检查清单

### 摄入与整理
- [ ] Inbox 每周按 4 条规则分流（移动 / 保留+note / 删除 / 隐私→private）
- [ ] 6 步增量节奏有节奏地推进（每周归档 / 每月复盘 / 项目与论文收尾 / 毕业前清理）
- [ ] 一条材料能说清自己在五层流水线的哪一层，raw 只追加不覆盖

### 边界与不变量
- [ ] raw 层配置只读追加；`99_Archive` 不新增/编辑/删除；`98_Private` 不进公开
- [ ] 大资产只写指针，不内联进 git
- [ ] 公开页无绝对机器路径、无用户名、无学号（grep 兜底）

### 外部源整合
- [ ] 开工前 `find -type f\|wc -l` + `du -sb` 记源基线
- [ ] 全程只复制/摘录/指针化，不改源
