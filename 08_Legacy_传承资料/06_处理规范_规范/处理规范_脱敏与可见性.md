## 边界说明

这页是 vault 的**脱敏 + 可见性 + 私有指针**单一规范，回答三个问题：

1. 一条内容该落在哪个可见性级别（public / internal / private）？
2. 蒸馏或公开前，哪些值必须脱敏、脱成什么？
3. 机器绝对路径怎么处理，才能既换机器可定位、又不泄漏进公开 git 树？

它和兄弟规范分工不重叠：

- 本页管 **visibility 分级 + 强敏感值脱敏 + 两半路径指针 + 公开/私有转换 + 验证 grep**。
- [[处理规范_蒸馏与归档]] 管**蒸馏工作流本身**（ingest → 蒸馏 → 快照 → closeout 的步骤与产物形态）；其中涉及脱敏时回引本页，不重复定义规则。
- [[处理规范_规范索引]] 是本类规范的总入口。

本页只写**规则与判定**，不登记具体敏感文件实例。穷举实例登记在 `99_Archive` 快照的 `06_敏感文件隔离清单.md`；私有绝对路径登记在 `98_Private_LOCAL_勿提交/资产指针索引_<date>.md`（见末节「关联」）。

## 适合谁读

- 第一次往本 vault 蒸馏 / 导入外部源（带绝对路径、用户名、机器布局）的师弟妹。
- 任何为本 vault 写整理 SOP、调 phd-self-os skill、或把内容标成 `visibility: public` 准备外发的智能体或人。
- 不确定「这条能不能进公开仓」「绝对路径怎么留」的人。

## 读完能做什么

- 用 visibility 三级的**操作定义**，给任意一页/一个文件定级。
- 识别强敏感值清单（学号 / 身份证 / 手机 / 邮箱 / token 形态 / 机器路径 / 用户名），并在蒸馏前脱敏。
- 把机器绝对路径拆成「公开页留相对 token + 私有指针留完整路径」两半。
- 对外发布前跑验证 grep，证明公开树干净。
- 知道在哪做穷举登记、在哪留私有指针。

## 1. visibility 三级操作定义

根 `README.md` 要求每篇笔记显式标注 `visibility: public/internal/private`。这里把三级从「标签」落实成**可执行的判定**：

| 级别 | 操作定义（落在哪、进不进 git） | 典型内容 |
|------|--------------------------------|----------|
| **public** | 进 git 公开树，可被任何人检索。**默认不包含**任何强敏感值、未发表结果、原始审稿意见、他人可识别信息。 | 已发表论文的公开笔记、可公开的方法论 / SOP / legacy 指南、已脱敏的复盘 |
| **internal** | 进 Obsidian 知识库，但**不进公开 git 提交**（`.gitignore` 或提交前剔除）。可含未发表结果、内部反馈原文、带路径的内部指针。 | 含未发表 idea 的项目页、导师 / 审稿反馈原文、含内部路径的工作流笔记 |
| **private** | 只进 `98_Private_LOCAL_勿提交/`，**永不入 git**。可含证件扫描、SSH 私钥、token、完整绝对路径指针、银行流水。 | 身份证 / 学生证、`.env` / `.netrc`、SSH 私钥、资产绝对路径索引 |

判定顺序（自上而下，命中即停）：

1. 命中 §2 强敏感值清单（token、证件号、明文密钥、银行流水） → **private**，落 `98_Private`。
2. 含未发表结果 / 原始审稿意见 / 带姓名的导师同伴评价 / 内部机器布局 → **internal**，不进公开 git。
3. 其余经 §4 公开/私有转换规则脱敏后可公开的 → **public**。

> 默认假设：**未显式标注或拿不准时，按 internal 处理**（来源：`privacy_policy.md`「Treat the vault as private unless the user explicitly marks the target output as public」）。宁可降级，不要误升级。

## 2. 脱敏闸：强敏感值清单

以下值**不得出现在 public 树**，internal 树中若出现要单独评估，private 树可保留。蒸馏 / 公开前必须逐类 grep 兜底（验证命令见 §5）。

### 2.1 个人识别号与联系方式

| 类别 | 模式 / 示例 | 处理 |
|------|-------------|------|
| 学号 | 形如 `<学号_redacted>`（10 位数字，清华学号形态） | 脱敏为 `<学号_redacted>` 或直接删除 |
| 身份证号 | 18 位（含校验位） | 永不公开；原件进 private 加密包 |
| 手机号 | 11 位中国大陆手机号 | 脱敏为 `<手机_redacted>` |
| 邮箱 | 私人邮箱（`@mails.tsinghua.edu.cn` 等） | 公开页改机构泛指或删除；公开主页邮箱除外 |

来源：根 `README.md`「公开前检查」；隔离清单 E 类（证件扫描）、F3 类（银行流水含姓名/账号）。学号脱敏形态来自 lesson（快照进公开仓前 22 文件 `<学号_redacted>` → `<学号_redacted>`）。

### 2.2 密钥 / Token 形态

下列**形态前缀**一律视为强敏感，无论前后文：

| 服务 | token 形态前缀 |
|------|----------------|
| OpenAI | `sk-` |
| GitHub PAT | `ghp_`、`gho_`、`ghu_`、`ghs_`、`ghr_` |
| AWS | `AKIA`（access key id 形态）、`ASIA`（临时） |
| 通用 Bearer | `Bearer ` |
| GitLab | `glpat-` |
| Slack | `xox`（`xoxb-` / `xoxp-` / `xoxa-`） |

> 同时 `.env` / `.netrc` / `auth.json` / `credentials.json` / `credentials.toml` / `id_rsa` / `*.pem`（非软件自带 CA）整文件视为 private，不读内容、只登记路径（见 §6）。来源：隔离清单 A/B/C/D 类。

### 2.3 机器绝对路径

这是**最易漏检**的一类——路径不像学号触发「敏感」直觉，蒸馏 agent 会原样抄源仓库里的路径（来源：lesson「为什么会发生」）。

| 类别 | 模式 | 脱敏目标 |
|------|------|----------|
| WSL 挂载盘符 | `/mnt/[a-z]/...`（`/mnt/k/`、`/mnt/d/`、`/mnt/e/`、`/mnt/c/`） | 公开页替换为可移植相对 token（见 §3） |
| Linux 主目录 | `/home/<user>/...`（`/home/<user>/`） | 公开页用 `~/` 或相对 token |
| Windows 盘符路径 | `C:\Users\...`、`D:\...` | 公开页去盘符 / 用户名，留语义尾部 |
| OneDrive 帐号路径 | `OneDrive - mails.tsinghua.edu.cn` | 公开页不出现帐号域 |

### 2.4 用户名 / 机器标识

| 标识 | 出现场景 | 处理 |
|------|----------|------|
| `<user>` | WSL 用户名、`/home/<user>/`、git 配置 | 公开页替换为 `~/` 或泛指 |
| `<user>` | GitHub 用户名、`<user>.github.io` | 公开页用 `@<github_redacted>` 或保留为公开主页链接（已公开则不脱） |
| `Administrator` | Windows 用户 `/mnt/c/Users/<user>/` | 公开页不出现 |

> `<user>` / 主页域名若本身已是公开身份（GitHub Pages、学术主页），可保留；只在与私有资产路径绑定出现时才脱。判定回到 §1 默认假设：拿不准就脱。

### 2.5 其他敏感类别（来自 privacy_policy.md）

下列即便不含上面可 grep 的值，也按 internal/private 处理，需人工或转换规则处理（见 §4）：

- 未发表手稿、未发表关键实验结果、可被抢发的 idea；
- 原始审稿意见、原始导师 / 同伴反馈；
- 对他人可识别的批评 / 评价（含导师、同门、被试、访谈对象）；
- 不宜公开的实验室内流程；
- 私人照片、私信、邮件、医疗 / 心理健康记录；
- 签证、就业、财务、个人证件；
- 机构冲突或人际纠纷。

来源：`privacy_policy.md`「Sensitive categories」。

## 3. 两半路径指针规则

**核心原则**：「路径指针」要拆成两半——公开页只留**相对 / 可移植 token**，完整**绝对机器路径**只进 gitignored 的私有指针索引。不要让绝对路径进公开 git 树。

来源：lesson「抽象原则 · 路径指针要拆成两半」。

### 3.1 公开页：留相对 token

公开蒸馏页里，把绝对路径替换成**去盘符 / 去用户名 / 去冗余前缀、保留语义尾部**的可移植 token：

| 源绝对路径（示例） | 公开页相对 token |
|--------------------|------------------|
| `/mnt/k/2_work/LQQL_OS/lqql_06_工作与项目/03_论文流水线/` | `LQQL_OS/论文流水线/` |
| `/mnt/k/2_work/LQQL_OS/.../R00-phmfactory/` | `LQQL_OS/论文流水线/R00-phmfactory/` |
| `/mnt/k/D01_vibench/` | `D01_vibench/` |
| `/mnt/d/paper/thesis/` | `paper/thesis/` |
| `/home/<user>/...` | `~/...` 或语义化 token |

替换策略：**specific-first sed**（先换最长前缀，再换短前缀，避免短前缀把长前缀的尾部吃掉）。保留有意义的尾部，去掉盘符 / 用户名 / 帐号域。

> 现有 vault 风格（如 [[毕业流程操作指南]]、[[答辩闭环SOP]]）本来就用相对文件夹结构、避免绝对路径——把它当**硬约束**，不是建议。

### 3.2 私有指针索引：留完整绝对路径

完整绝对路径 + 资产说明 + 来源 sha256 集中登记到私有区，便于换机器后重新定位：

- 落点：`98_Private_LOCAL_勿提交/资产指针索引_<date>.md`（该目录已 gitignore，**不进公开仓库**）。
- 字段：`相对 token` ↔ `绝对路径` ↔ `说明 / 体积 / 来源哈希`（范式见 `资产指针索引_2026-07-09.md`，按盘分节列表）。
- 命中机器路径时：先建 / 更新该索引，再对公开页跑 sed 替换。顺序不能反——索引是真相源，公开页只是它的脱敏投影。

### 3.3 为什么不能只靠 prompt

蒸馏 agent 即便被要求「脱敏」，仍会原样抄源里的路径与用户名——路径 / 用户名不像学号触发敏感直觉。**必须靠 §5 的验证 grep 兜底，不能只靠 prompt 约束**（来源：lesson「抽象原则」「可执行清单」）。

## 4. 公开 / 私有转换规则

把一条 internal/private 内容转成 public 时，按下表变换。来源：`privacy_policy.md`「Public-facing transformation rules」 + `SKILL.md`「Privacy and safety rules」。

| 维度 | public 转换动作 |
|------|-----------------|
| 人名 | 匿名化（除非该人 / 该身份已公开且与内容相关） |
| 日期 | 非必要时不留精确日期，用近似时段 |
| 路径 | 删除私有路径，或按 §3 换成相对 token |
| 未发表结果 / 方法 | 删除 |
| 反馈 / 评价 | **改写（paraphrase）而非直引**；把可识别批评转成「流程 / 沟通 / 预期差异」层面的教训 |
| 直接引语 | 不直引原始反馈，区分「直引 / 转述 / 个人解读」三者，公开页只留转述后的教训 |

针对第三方（导师、合作者、同门、审稿人、被试、访谈对象、行政、朋友）的额外约束（来源：`privacy_policy.md`「Third-party people」）：

- 不推断动机，不把意图归因到超出笔记所写；
- 避免单方面道德标签；
- 优选「这次互动暴露了流程 / 沟通 / 预期问题」，避免「某某就是……」。

internal（私有知识库内部）的转换规则相反——**保留摩擦，不要磨平**（来源：`privacy_policy.md`「Internal-facing transformation rules」）：

- 保留源链接；
- 保留不确定性；
- 直引与转述分开标注；
- 记录未解问题；
- 不要把有用的摩擦打磨掉。

## 5. 验证 grep 清单（蒸馏后必跑）

**每完成一次蒸馏 / 导入 / 公开发布，必跑下列 grep 兜底**（来源：lesson「可执行清单」）。任一命中都需处理（脱敏或迁私有指针）后才能提交公开仓。

```bash
# ① 强敏感值（token 形态 + 个人识别号）
grep -rnE 'sk-[A-Za-z0-9]|ghp_|gho_|ghu_|ghs_|ghr_|AKIA[A-Z0-9]|ASIA[0-Z]|Bearer [A-Za-z0-9._-]|glpat-|xox[bpa]-' <蒸馏目标树>
grep -rnE '[0-9]{10}' <蒸馏目标树>          # 学号 / 手机形态（人工确认是否真敏感）
grep -rniE '[A-Za-z0-9._%+-]+@mails\.tsinghua\.edu\.cn' <蒸馏目标树>  # 私人邮箱

# ② 机器路径与用户名（最易漏）
grep -rnE '/mnt/[a-z]/' <蒸馏目标树>         # WSL 盘符
grep -rnE '/home/[a-z_]+' <蒸馏目标树>       # Linux 主目录
grep -rniE '<user>|Administrator' <蒸馏目标树>   # 用户名 / Windows 用户
# Windows 盘符路径
grep -rnE '[A-Z]:\\\\' <蒸馏目标树>
```

要求：**公开蒸馏树** `/mnt`、`/home/<user>`、`<user>`、token 前缀命中归零（lesson 复验标准）。学号类命中按 §2.1 脱敏。

> 忠实快照（`99_Archive`）是另一套规则——快照保留源原貌（含源里的学号 / 路径），**若快照要进公开仓**，须对快照单独 grep 学号并 sed 脱敏（如 `<学号_redacted>` → `<学号_redacted>`），并在 README 注明「文件名引用中学号已脱敏，内容忠实」（来源：lesson「抽象原则 · 忠实证据快照 ≠ 蒸馏页」）。

源不变性双测（针对从外部源 COPY 进来的任务）：

- 开工前：`find <src> -type f | wc -l` + `du -sb <src>` 记基线；
- 收尾重测，逐字节比对，证明 COPY-ONLY 没误写源（来源：lesson「可执行清单」末条）。

## 6. 穷举登记与指针落点

本页只写规则，不登记实例。实例登记走两处，规则如下：

### 6.1 敏感文件穷举登记

- 落点：`99_Archive_归档/A0_毕业整理_snapshot_202606/06_敏感文件隔离清单.md`（忠实快照区）。
- 登记维度：**路径 / 类型 / 大小 / 修改时间 / 风险等级 / 处理建议**——**只登记元数据，禁止读取 / 打印 / 复制文件内容**。
- 覆盖范围（来源：该清单摘要）：SSH 私钥、PEM 证书、API token / `.env` / `.netrc` / 凭证文件、Docker / Jupyter / 浏览器 / Codex 沙箱 / 设备认证、证件扫描件（身份证 / 学生证 / 毕业证 / 学位证 / 成绩单 / 户口）、电子签名 / 财务凭证 / 银行 / 支付宝 / 微信流水、含他人隐私的答辩材料。
- 软件自带 CA / 测试证书不计入（无个人密钥，风险无）。
- 加密包分多个独立单元（如 `encrypted_identities` / `encrypted_ssh_keys` / `encrypted_api_tokens` / `encrypted_mails_archive`），各自独立密码，降低一次性失守风险。

### 6.2 资产绝对路径指针

- 落点：`98_Private_LOCAL_勿提交/资产指针索引_<date>.md`（gitignored，**永不入 git**）。
- 范式：按盘分节（K 盘 / D 盘 / E 盘 + WSL 主目录），列 `相对 token ↔ 绝对路径 ↔ 说明 / 体积`，附完整性校验（sha256 出处）与换机器恢复路径（优先夸克冷存储备份，无法恢复时用本表绝对路径 + hash_all.tsv 重新定位）。
- 见现有 `资产指针索引_2026-07-09.md` 的写法，新增资产按同结构追加。

> 两处关系：隔离清单管「这个文件敏感、要不要隔离 / 加密」；指针索引管「这个相对 token 背后的绝对路径在哪」。蒸馏时命中机器路径 → 更新指针索引；命中强敏感文件 → 进隔离清单。

## 常见坑

| 坑 | 表现 | 解决办法 |
|---|---|---|
| 绝对路径漏检 | 蒸馏页原样抄 `/mnt/k/...`、`/home/<user>/`，其中 public 页也中招 | §3 两半指针 + §5 grep 兜底，不能只靠 prompt |
| 路径指针歧义 | 「路径指针」既被理解成公开页里的路径、又被理解成私有区指针文件 | 明确拆两半：公开留相对 token，绝对路径只进私有索引 |
| 学号脱敏不一致 | 快照里学号原样、蒸馏页脱敏、两边对不上 | 快照进公开仓前单独 sed 学号并在 README 注明「文件名引用已脱敏，内容忠实」 |
| visibility 默认 public | 拿不准就标 public，未发表 idea 进了公开仓 | 默认 internal，命中强敏感才 private，显式确认脱敏后才升 public |
| 反馈原文直引进 public | 把导师 / 审稿原话贴进公开页 | public 页只留 paraphrase 后的教训；原文留 internal |
| 第三方动机推断 | 「某某就是……」式归因 | 只写「这次互动暴露了流程 / 沟通 / 预期问题」，不归因动机 |
| 私钥 / token 进 git | `.env` / `id_rsa` 被当普通附件提交 | 整文件进 private / 加密包；公开仓 grep token 前缀形态 |
| 快照 ≠ 蒸馏页规则混用 | 用蒸馏页的脱敏规则去要求忠实快照，或反过来 | 快照保留源原貌（进公开仓才单独脱学号）；蒸馏页按 vault 风格去绝对路径 |

## 检查清单

蒸馏 / 导入 / 公开发布前逐项核对：

- [ ] 给每篇笔记定了 `visibility: public/internal/private`（默认 internal）
- [ ] 强敏感值（学号 / 身份证 / 手机 / 邮箱 / token 形态）已脱敏或迁 private
- [ ] 机器绝对路径已拆两半：公开页留相对 token，完整路径进 `资产指针索引_<date>.md`
- [ ] 用户名（`<user>` / `Administrator`）在公开页已脱
- [ ] 反馈 / 评价已 paraphrase，未直引他人原话进 public
- [ ] 跑过 §5 两条 grep：① 强敏感值；② 机器路径与用户名
- [ ] 公开蒸馏树 `/mnt`、`/home/<user>`、`<user>`、token 前缀命中归零
- [ ] 源不变性双测通过（外部 COPY 任务）：`find/du` == 基线
- [ ] 命中的敏感文件已登记进隔离清单（路径 / 类型 / 大小 / 时间 / 风险，不读内容）
- [ ] 快照若进公开仓，已单独 grep 学号并 sed，README 已注明

## 示例

把 `D:\A0_博士毕业数据总仓库\A0_毕业整理\` 的 14 张 OS 卡片蒸馏进本 vault 时（lesson 场景）：强敏感值（学号 / token / 邮箱 / 电话）0 命中，脱敏到位；但 10 个公开蒸馏页原样抄进了源卡片的 `/mnt/...` 与 `/home/<user>/`，其中 4 页还是 `visibility: public`。修法是：先 grep 出全部命中与去重前缀 → 建 `98_Private/资产指针索引_2026-07-09.md` 集中绝对路径 → 对 10 个公开页跑 specific-first sed 换成相对 token → 复验 `/mnt` 与 `<user>` 命中归零。结论：路径 / 用户名必须靠 grep 兜底，prompt 约不住。
