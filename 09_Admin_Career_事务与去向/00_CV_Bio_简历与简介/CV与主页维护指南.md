# CV 与主页维护指南

> 来源: 博士毕业源仓库 os_cards/020_个人主页与CV.md
> 整理日期: 2026-07-09
> 适用范围: 个人学术主页（jemdoc + Jekyll 双站点）+ 中英 CV + 发表论文方法图的维护与更新流程

---

## 边界说明

这页是**维护流程与方法**，不是 CV 正文、不是主页源码本身。

- 是什么：jemdoc 主页和 Jekyll 站点的结构、CV（中英）的更新节奏、4 张方法图（ADIG / AMDA / EGAN / KMADA）的复用方式，以及"什么时候该更新什么"的 SOP。
- 不是什么：不含 CV 全文、不含个人照片、不含主页 HTML/CSS 全文。CV PDF、主页源码、个人照片只写**私有指针**（见下），公开页只记流程 + 结构 + 指针。
- 本页是 [[学术主页自动化]] 的"工程上游"姊妹页：本页讲"维护什么、怎么改"，那页讲"Google Scholar crawler / jemdoc→Jekyll 怎么自动化"。

## 适合谁读

- 即将毕业、要给导师 / 求职单位 / 国际合作者发主页和 CV 的博士生。
- 想复用 jemdoc + Jekyll 学术主页模板、但不知道结构怎么组织的人。
- 已经有主页和 CV、但版本失控（中英不同步 / 主页没跟上最新论文）的人。

## 读完能做什么

1. 知道主页和 CV 的双站点结构、各自负责什么。
2. 按 SOP 在发新论文 / 申博后 / 改联系方式时同步更新主页与 CV。
3. 把 4 张方法图作为可复用资产，接到新论文 figure 里。

## 前置条件

- 一个可写的 GitHub Pages 仓库（用于 Jekyll 站点托管）。
- 本地或服务器上保留主页源码工作副本（jemdoc + CSS）。
- CV 的可编辑源文件（LaTeX / Word），不只是 PDF。
- 私有区有存放 CV PDF、照片、源码的指针位置（见末尾"私有指针"）。

## 标准流程

### 1. 先认清双站点结构

主页是**两套并存的站点**，职责不同，不要混改：

| 站点 | 技术栈 | 职责 | 当前状态 |
|---|---|---|---|
| 主站 | jemdoc + `jemdoc.css` + `index.html` | 清华机械系官方个人主页（挂在系域名下），对外名片 | 对外正式入口 |
| 个人站 | Jekyll（GitHub Pages，`Richie_Li.github.io-main` / `liq22.github.io`） | 个人学术博客 + Google Scholar 自动抓取 + 长期可迁移 | 工程化、可自动化 |

**分工原则**：主站（jemdoc）求稳、求官方；个人站（Jekyll）求新、求自动、求可脱离学校环境。毕业后学校主页可能失效，长期身份资产要落到个人站 + GitHub。

### 2. 主页（jemdoc）的维护点

主站源码结构（来自源卡片，已脱敏为结构指针）：

- `index.html` — 主页正文（个人信息、研究方向、论文列表、链接）。
- `jemdoc.css` — 主页样式表（jemdoc 生成 HTML 时套用）。
- `pic/` — 三类图片：
  - **头像**：`Liqi*.png/jpg`（个人照片，**敏感原件，见私有指针，不在公开页内联**）。
  - **社交图标**：Google Scholar / ResearchGate / GitHub 的 logo（公开可复用）。
  - **方法图**：ADIG / AMDA / EGAN / KMADA（见下"方法图复用"）。

更新 jemdoc 主页的标准动作：
1. 改 `index.html` 对应段落（论文列表 / 联系方式 / 研究简介）。
2. 新论文配上对应方法图到 `pic/`。
3. 本地预览 jemdoc 编译结果。
4. 推到系服务器（部署路径见私有指针）。

### 3. CV（中英双份）的维护节奏

CV 是"硬通货"，是博后申请 / 求职 / 国际合作的直接附件，**中英两份必须同步**。

| CV | 语言 | 源文件形态 | 用途 |
|---|---|---|---|
| 英文 CV | EN | 可编辑源（LaTeX/Word）→ `CV_Qi_Li_v2.4.pdf` | 国际合作 / 英文申请 |
| 中文简历 | ZH | 可编辑源 → `简历2025_*.pdf`（跨域引用论文库） | 国内求职 / 行政材料 |

CV 标准段落（两份都要有、且互相对应）：
- 教育（Education）
- 研究兴趣（Research Interests）
- 论文（Publications）— 与 [[Publication_Map]] 对齐
- 项目（Projects）
- 技能（Skills）
- 荣誉（Honors / Awards）

**更新触发点**（出现下列任一情况，立刻改 CV 并升版本号）：
- 发表 / 录用新论文。
- 获新荣誉 / 奖项。
- 联系方式变更（邮箱、主页 URL）。
- 进入新阶段（答辩通过、毕业、入职）。

**版本约定**：CV 文件名带版本号（如 `v2.4`），每次重大更新升 minor 版本；避免"最终版 / 最终版2 / 真正最终版"。

### 4. 方法图（ADIG / AMDA / EGAN / KMADA）复用

主页 `pic/` 下挂着 4 张已发表论文的方法图，是**可复用资产**，写新论文 figure 时可直接作为框架图起点：

| 方法图 | 全称（推测） | 复用场景 |
|---|---|---|
| ADIG | 自适应增量域泛化（Adaptive / Incremental Domain Generalization） | 域泛化类论文 framework 图 |
| AMDA | 自适应多源域适配（Adaptive Multi-source Domain Adaptation） | 多源域适配 pipeline 图 |
| EGAN | 嵌入式 GAN（Embedded GAN） | GAN 结构 / 模块嵌入图 |
| KMADA | 知识映射对抗域适配（Knowledge-Map Adversarial Domain Adaptation） | 知识 + 对抗域适配框架图 |

复用注意：
- 方法图对应的是**已发表**工作，复用时改清来源、不要直接冒充新方法的图。
- 具体论文与图的对应关系见 [[Publication_Map]] 和 [[ADIG_早期代表作]]。
- 图源文件（矢量 / 高清）只放私有指针，公开页不内联大图。

### 5. 联系方式与外部链接同步

主页和 CV 上的链接要互相对得上、且都活：
- Google Scholar 主页（持续更新论文）。
- ResearchGate。
- GitHub（个人站源码仓库）。
- 学校官方主页 URL。

任一链接失效（如学校主页毕业后续费问题）要立刻在个人站做重定向。

## 常见坑

| 坑 | 表现 | 解决办法 |
|---|---|---|
| 中英 CV 不同步 | 英文 CV 已更新论文，中文简历还停在半年前 | 把"改 CV"和"发论文"绑成一个动作，发一篇改两份 |
| 版本号混乱 | 出现"最终版 / 真正最终版" | 文件名强制带语义版本号（v2.4），每次更新升号 |
| 学校主页毕业失效 | 毕业离校后系域名下主页被收回，外部链接全断 | 长期身份资产放到个人 Jekyll 站 + GitHub，学校主页只作临时入口 |
| 照片 / 源码误传公开仓库 | 个人照片或 CV 全文被推进公开 git | 照片 / CV PDF / 源码只进私有区，公开页只留指针（见脱敏规则） |
| 方法图直接冒用 | 把已发表论文的方法图原样当新论文 figure | 复用时改清来源标注，区分"复用框架"与"新图" |

## 检查清单

每次更新主页 / CV 后过一遍：

- [ ] 中英 CV 同步更新，版本号已升。
- [ ] 主站（jemdoc）和个人站（Jekyll）论文列表一致。
- [ ] 新论文已配上方法图到 `pic/`，并与 [[Publication_Map]] 对齐。
- [ ] 联系方式 / 外部链接全部有效（点得开）。
- [ ] 个人照片、CV PDF、源码**没有**进公开 git（在私有区）。
- [ ] GitHub Pages 个人站可正常访问。

## 示例

**一次典型更新（发新论文后）**：
1. 在 CV 中英两份的 Publications 段加入新论文 → 升版本号 v2.4 → v2.5。
2. 主站 `index.html` 论文列表追加条目，方法图放 `pic/`。
3. 个人站 Jekyll 同步更新（若已接 Google Scholar crawler，可半自动）。
4. 更新 [[Publication_Map]] 里该论文的阶段标记。
5. 全部预览无误后部署主站、推送个人站。

## 最容易卡住的地方

1. **把维护当成一次性活**：主页和 CV 不是"写一次就好"，而是随发表节奏持续滚动维护，最容易拖到要投简历当天才发现没更新。
2. **双站点职责不清**：jemdoc 主站和 Jekyll 个人站改混，导致两边不一致。记住"主站稳、个人站新"。
3. **毕业身份迁移被忽略**：学校主页有保质期，毕业前后不把长期身份资产迁到个人站，链接会批量失效。
