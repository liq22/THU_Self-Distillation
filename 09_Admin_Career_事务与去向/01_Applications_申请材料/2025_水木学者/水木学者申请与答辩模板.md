# 水木学者申请与答辩模板

## 边界说明

本页是给师弟妹的**水木学者申请与答辩模板**，沉淀自一份完整的水木学者申请 + 答辩实战材料。它讲的是"申请书怎么写、答辩 PPT 怎么排、Q&A 怎么备"，不是申请书正文本身。GitHub 公开版不保存申请书原件、推荐意见、汇总表、答辩 PPT 原件和个人编号——这些只走私有指针。

> 敏感原件与大体积资产只写私有指针, 规则见 [[处理规范_脱敏与可见性]]。

## 适合谁读

- 清华机械系（或相关方向）准备申报水木学者 / 同级人才计划的博士生或刚进站博后。
- 第一次写这类人才计划申请书、不知道材料结构怎么切、答辩 PPT 怎么组织、Q&A 怎么应对的人。

## 读完能做什么

- 按"基本信息 / 教育研究经历 / 代表性成果 / 研究计划 / 合作基础 / 未来发展"六模块搭申请书骨架。
- 用六段式答辩 PPT 结构（个人定位 → 博士主线 → 代表成果 → 未来计划 → 平台匹配 → 风险应对）排答辩稿。
- 提前备好四类高频 Q&A（为什么申请 / 计划是否可行 / 个人贡献 / 与团队关系）的回答框架。

## 前置条件

- 已确定申请定位与研究方向（能一句话说清"做什么、为什么是我做"）。
- 代表性成果已成形（至少 2-3 项能支撑定位的成果）。
- 合作导师、平台、团队资源已基本谈拢。

## 申请材料结构

| 模块 | 写作目标 |
|---|---|
| 基本信息 | 准确、简洁，和 CV 保持一致 |
| 教育与研究经历 | 强调博士阶段主线和独立性 |
| 代表性成果 | 只选能支撑申请定位的成果 |
| 研究计划 | 明确 1-3 年问题、路线和产出 |
| 合作基础 | 说明平台、导师、团队和资源匹配 |
| 未来发展 | 说明为什么适合该计划 |

## 答辩 PPT 结构

1. 个人定位：一句话说明研究方向和申请目标。
2. 博士主线：用时间线说明问题如何收敛。
3. 代表成果：每个成果说明问题、方法、贡献和影响。
4. 未来计划：问题、技术路线、阶段产出。
5. 平台匹配：为什么该平台能支撑这项工作。
6. 风险与应对：数据、合作、论文、时间安排。

## Q&A 准备

| 问题类型 | 准备方式 |
|---|---|
| 为什么申请这个计划 | 从研究延续、平台匹配、个人发展回答 |
| 未来计划是否可行 | 拆成近期可做、中期突破、长期目标 |
| 代表成果中的个人贡献 | 准备角色边界和具体贡献 |
| 和已有团队/方向的关系 | 说明互补性，不夸大独立资源 |

## 常见坑

| 坑 | 表现 | 解决办法 |
|---|---|---|
| 申请书堆所有成果 | 把全部论文塞进代表性成果，定位被稀释 | 只选能支撑申请定位的成果，其余放 CV |
| 研究计划过宽 | 1-3 年问题铺得太开，看不出可落地 | 收敛到明确问题 + 路线 + 阶段产出，能说清"近期可做、中期突破、长期目标" |
| 个人贡献边界模糊 | 被问"你的具体贡献"时答不出角色边界 | 每个成果提前备好角色边界 + 具体贡献说明 |
| 夸大独立资源 | 为显独立把团队 / 平台资源说成自己独有 | 说明与已有团队的互补性，不夸大独立资源 |
| 答辩超时 | 代表成果每项讲太细，压不进规定时长 | 每个成果固定"问题→方法→贡献→影响"四句话 |
| 敏感件误进公开仓库 | 申请书原件 / 推荐意见 / 汇总表被推进公开 git | 公开页只留结构与经验，原件只走私有指针（见 GitHub 上传边界） |

## 检查清单

- [ ] 申请书六模块齐全（基本信息 / 教育研究经历 / 代表性成果 / 研究计划 / 合作基础 / 未来发展）
- [ ] 代表性成果只选能支撑定位的，已与 [[Publication_Map]] 对齐
- [ ] 研究计划有明确 1-3 年问题、路线、阶段产出
- [ ] 答辩 PPT 六段式排好，代表成果控制在时长内
- [ ] 四类高频 Q&A 已备回答框架
- [ ] 个人贡献 / 角色边界已逐项准备
- [ ] 申请书原件、推荐意见、汇总表、答辩 PPT、个人编号**没有**进公开 git（只走私有指针）

## GitHub 上传边界

- 可提交：材料结构、答辩结构、准备经验。
- 不提交：申请书原件、推荐意见、汇总表、答辩 PPT、个人编号、联系方式。
