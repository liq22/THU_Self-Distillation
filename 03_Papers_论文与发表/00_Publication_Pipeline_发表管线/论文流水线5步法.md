# 论文流水线 5 步法

> 来源: os_cards/012_已发表与在投论文闭环.md ("论文流水线方法论 5 步法" 小节, 脱敏提炼)
> 整理日期: 2026-07-09
> 适用范围: 从 idea 到 published 的完整投稿生命周期方法论; 引用 012 的 5 步法

## 边界说明

这一页是论文投稿生命周期的**方法论骨架**, 覆盖 Idea → Draft → Submitted → Revision → Accepted → Published 全链条。不收录任何具体论文的正文、审稿意见、投稿通信原件 (敏感, 见私有指针)。具体论文状态见 [[Publication_Map]]。

## 适合谁读

如果你是清华机械系/相关方向的博士生, 第一次要把一个 idea 一路推到 published; 或者你正在管多篇并行投稿、想要一套可复用的工作法来降低单篇决策成本, 这篇指南面向你。

## 读完能做什么

- 把一个模糊的 idea 沿同一条 5 步路径推到正式发表, 不为每篇论文重新发明流程。
- 在每个阶段都留下可追溯的产物 (思路图 / git commit / LaTeX 源 / 归档目录), 让任何一张 figure 都能回溯到代码与思路。
- 避开"有 idea 不落地""返修归档不全""figure 与代码脱钩"几个最常见的卡点。

## 场景

博士期间累计 5 篇已发表 + 14 篇在投, 若全部录用 SCI 论文将达 19+ 篇 (其中 4 篇校样稿 TII/IoT/MST/SMCA 即将见刊)。这条流水线是支撑这一产出的可复用工作法。

## 如果你第一次走投稿, 先认清这两个坑

- 论文生产如果不流程化, 容易卡在"有 idea 但不落地"或"写了一半丢进文件夹再也找不到"。
- 投稿后返修如果没把每轮通信、每个 figure 的代码版本归档, 后期无法复现, 也无法快速做扩展版。

## 后来怎么解决 (5 步法)

> 以下 5 步直接引用源 012 的"论文流水线方法论 (5 步法)", 路径脱敏为指针。

### 第 1 步: Idea 起草
- 工具: OneNote / drawio / xmind。
- 产出: 思路图 (`思路.drawio` + `PHD papers.xmind`)。
- 作用: 把模糊想法结构化为可执行的研究问题。

### 第 2 步: 实验代码 → figure
- 位置: K 盘 `_Richie_project/` 与 D 盘 `10.project/`。
- 产出: 实验代码 + 实验 figure。
- 作用: 用实验验证 idea, 产出论文级 figure。

### 第 3 步: 起稿 → 拒稿 → 返修 → 转 LaTeX
- 流程: Word 起稿 → (可能) 拒稿 → 多次返修 → 转 LaTeX。
- 版本: `JMS_DENpass/.git` 等含完整 git 历史, 可追溯每个 figure 的代码版本。
- 作用: 把实验结果组织成可投稿手稿。

### 第 4 步: Overleaf 协作 → 提交 → Reviewer → Response → Proof
- 工具: Overleaf 协作。
- 流程: 提交 → Reviewer Comments → Response to Reviewer → 校样 (Proof)。
- 展开见 [[Response与CoverLetter写作方法论]]。

### 第 5 步: 发表与归档
- PDF 收录: `小论文正式版/`。
- 全文 OCR: `txt/` (供 OS 全文检索)。
- 作用: 形成可被简历/基金/扩展版复用的正式资产。

## 抽象原则

- **流水线化降低决策成本**: 每篇论文走同一条 5 步路径, 不为单篇重新发明流程。
- **每步都留可追溯产物**: drawio/xmind (思路) → git (代码) → LaTeX (手稿) → 归档目录 (发表件), 全链可回溯。
- **拒稿是流程内事件, 不是失败**: 第 3 步显式包含"拒稿 → 返修 → 重投", 把拒稿纳入预期路径。

## 可执行清单

- [ ] 第 1 步: 是否有 drawio/xmind 思路图归档?
- [ ] 第 2 步: 实验 figure 是否在 git 中有对应 commit?
- [ ] 第 3 步: 手稿是否有 git 历史 + LaTeX 源?
- [ ] 第 4 步: 每轮 Reviewer / Response 是否归档 (脱敏, 见私有指针)?
- [ ] 第 5 步: 发表 PDF + OCR txt 是否双份归档?
- [ ] 全链路: 是否能从任何一个 figure 回溯到代码 commit 与思路图节点?

## 适用边界

- 本 5 步法基于个人 PHM/故障诊断领域的 IEEE 期刊投稿经验; 理论/计算/社科类期刊的协作与返修节奏可能不同。
- 第 5 步的"OCR txt 供 OS 检索"是个人知识管理偏好, 非期刊要求。

## 最容易卡住的地方

- **第 2 步 figure 与代码脱钩**: 没有在 git commit 里写清"本提交对应论文 figure X", 后期无法复现。
- **第 3 步 Word → LaTeX 转换时机**: 转太早损失写作速度, 转太晚返修痛苦; 经验是返修稳定后再转。
- **第 4 步返修归档不全**: 只留最终 Response, 丢中间轮次, 做扩展版时找不到演化逻辑。
- **第 5 步只存 PDF 不存 txt**: 全文检索依赖 txt, 只存 PDF 后期 OS 检索不到。
