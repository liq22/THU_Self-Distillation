# Response 与 Cover Letter 写作方法论

> 来源: os_cards/012_已发表与在投论文闭环.md (DEN / TIFN / ADIG 的 Cover Letter 与 Response 档案, 脱敏提炼)
> 整理日期: 2026-07-09
> 适用范围: 期刊投稿的 Cover Letter 与 Reviewer Response 写作方法; 脱敏, 不附任何原文

## 边界说明

这一页只记**写作方法与结构**, 不收录任何 Response / Cover Letter / Reviewer Comments 原文——这些是投稿通信原件, 属敏感材料, 只在私有区留指针。本页是个人多篇论文 (DEN / TON / TIFN / ADIG, 跨 JMS / TII / INFFUS / RESS) 投稿返修经验的脱敏提炼。

## 场景

博士期间 5 篇代表作 + 14 篇在投, 每篇都经历了完整投稿生命周期 (投稿-拒稿-重投-返修-录用-校样-发表), 含全部 Cover Letter、Response to Reviewer、Reviewer Comments。这种完整性在科研档案中较为罕见, 是 Cover Letter / Response 写作的活教材。

## 当时的问题

- 第一次写 Response 时容易"逐条复述审稿意见 + 笼统说已修改", 没有点明改在论文哪里, 审稿人回查困难。
- Cover Letter 容易写成论文摘要的复读, 没有传递"为什么这篇值得发表"的增量信号。

## 为什么会发生

- Response 的本质是**说服审稿人**, 而不是"汇报修改动作"; 混淆这两者会导致回复流于表面。
- Cover Letter 的读者是**编辑** (决定送审/拒稿), 与摘要的读者 (研究者) 不同, 复读摘要无法传递编辑需要的"范围契合 + 增量贡献"信号。

## 后来怎么解决 (写作结构)

### Response to Reviewer 的结构

1. **开场致谢 + 整体说明**: 简短感谢, 一句话点明本轮修改的整体方向与主要变化。
2. **逐条回复**, 每条固定四段式:
   - 引用审稿人原意 (脱敏, 不贴原文)
   - 表态: 同意 / 部分同意 / 礼貌不同意
   - 具体修改: 说明**改在论文哪一节、哪一段**, 必要时给出修改前后对比
   - (若不同意) 给出有理有据的反驳依据, 而非情绪化辩护
3. **收尾**: 列出本轮修改清单 (章节级), 方便审稿人核对。

### Cover Letter 的结构

1. **投稿声明**: 论文标题、期刊、稿件编号 (若有)、未一稿多投声明。
2. **范围契合**: 一句话说明论文与期刊范围/读者群的契合点。
3. **增量贡献**: 2–3 条, 用编辑视角讲清"这篇比现有工作多解决了什么", 避免与摘要逐字重复。
4. **(重投时) 改动概览**: 上一轮主要意见 + 本轮如何回应, 附 Response 文件指引。
5. **通讯与利益声明**: 通讯作者信息、利益冲突声明 (敏感, 见私有指针, 不入公开页)。

## 抽象原则

- **Response 是说服, 不是汇报**: 每条回复都要让审稿人能 30 秒内确认"这条被认真对待 + 改在哪"。
- **Cover Letter 服务编辑, 不是复读摘要**: 编辑关心范围契合与增量, 不关心方法细节。
- **逐条对齐 + 位置定位**: 永远给出修改在论文中的精确位置, 降低审稿人回查成本。
- **拒稿 ≠ 终点**: reject 后重投 (如 TIFN 在 INFFUS 的 reject → resubmission) 是常态, Cover Letter 要重写"改动概览"段, 不能复用首投版。

## 可执行清单

- [ ] Response 每条是否都包含: 引用原意 / 表态 / 修改位置 / (必要时) 反驳依据?
- [ ] 修改位置是否精确到"第 X 节第 Y 段"或给出修改前后对比?
- [ ] Cover Letter 是否有"范围契合 + 增量贡献"两段, 且未与摘要逐字重复?
- [ ] 重投时是否更新了 Cover Letter 的"改动概览"段?
- [ ] 是否避免贴入 Reviewer Comments 原文 (脱敏要求)?
- [ ] 修改后论文版本号 / 文件名是否与系统提交一致?

## 适用边界

- 本方法论基于个人 JMS / TII / INFFUS / RESS 投稿经验, 偏工程与 PHM 领域; 理论/计算期刊的审稿文化可能不同, 套用前先看目标期刊近年 Response 风格。
- 不同期刊对 Response 格式有模板要求 (字数、是否单独文件), 以期刊 Author Guidelines 为准, 本页只给结构层方法。

## 最容易卡住的地方

- **"同意修改但口径不一致"**: 多条 Response 之间对同一概念表述不统一, 审稿人会质疑严谨性; 写完统一过一遍术语表。
- **反驳语气温吞或过激**: 反驳要有依据但不挑衅, 卡在这两端都容易被记恨。
- **修改位置描述含糊**: "已在文中修改"是最差回复, 必须给具体位置。
