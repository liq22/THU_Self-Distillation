## C. 上传中断后恢复策略

### C.1 rsync 续传 (本地 → 本地总仓库)

```bash
# 中断后续传, 跳过已完整传输的文件
rsync -avh --partial --append-verify --inplace \
  --exclude='.git/' --exclude='__pycache__/' --exclude='wandb/' \
  "/mnt/k/D01_vibench/" \
  "/mnt/t/博士毕业数据总仓库_202606/03_实验数据与结果/vibench/"
```

### C.2 夸克客户端续传 (本地总仓库 → 夸克云)

- 夸克客户端默认断点续传, 网络中断后会自动继续
- 若夸克客户端崩溃, 重启后继续未完成的上传任务
- 若夸克网页版上传失败 (大文件), 改用客户端拖拽
- **单文件 > 100 GB 不能上传**, 必须分片 (见 B06 ViBench 处理)

### C.3 失败重传清单

每批次若部分文件失败, 在 `_intermediate/logs/upload_failures_BNN.csv` 记录:

```csv
src_path,dst_path,error,ts,retry_count
/mnt/k/D01_vibench/file_3.h5,...,network_timeout,2026-06-09T10:30:00,2
```

下次重试时仅传 failure 列表中的文件.
