### A.4 git bundle 备份 (3 个有 .git 的项目)

```bash
# 理由: ViBench / 7_13logic / LQQL_OS 这 3 个仓库含 .git 历史 (~3 GB), 直接 rsync .git 风险高
#       (objects 可能损坏), git bundle 把整个历史压成单一二进制文件, 离线恢复用 `git clone bundle`.
# 风险: 无 (只读源 + 写 bundle). 见 00 §6 已知限制 4.
# 输出: /mnt/t/博士毕业数据总仓库_202606/02_科研项目与代码/*/_git_bundle/*.bundle

BUNDLE_DIR="/mnt/t/博士毕业数据总仓库_202606/02_科研项目与代码/_git_bundles"
mkdir -p "$BUNDLE_DIR"

# dry-run: 列出 3 个仓库分支
for repo in "/mnt/d/paper/paper_25_9_vibench" "/mnt/k/2_work/7_13logic" "/mnt/k/2_work/LQQL_OS"; do
  if [[ -d "$repo/.git" ]]; then
    echo "[BUNDLE-DRY] $repo"
    git -C "$repo" branch -av
    git -C "$repo" tag
  else
    echo "[BUNDLE-SKIP] $repo (.git 不存在)"
  fi
done

# execute: 实际打包 (--all 含所有分支 + tag)
for repo in "/mnt/d/paper/paper_25_9_vibench" "/mnt/k/2_work/7_13logic" "/mnt/k/2_work/LQQL_OS"; do
  if [[ -d "$repo/.git" ]]; then
    name=$(basename "$repo")
    out="$BUNDLE_DIR/${name}_$(date +%Y%m%d).bundle"
    git -C "$repo" bundle create "$out" --all
    echo "[BUNDLE-OK] $out ($(du -h "$out" | cut -f1))"
  fi
done
```

## §D 人工确认后执行 (高风险, 每条 rm 前必须 # 禁止自动执行)

> **本节所有命令默认不执行**: `USER_CONFIRMED_DELETE=0`, 必须先在 shell `export USER_CONFIRMED_DELETE=1` 才会跑.
> **每条 rm 前一行**: `# 禁止自动执行 — <理由>`
> **所有 rm 用 -i**: 交互式确认每个文件
> **理由必填**: 见每条 `# 禁止自动执行` 行

```bash
#!/usr/bin/env bash
# scripts/cleanup_after_confirm.sh
# 所有删除/清空命令集中在此. 默认 USER_CONFIRMED_DELETE=0, 即使 source 也不跑.
set -uo pipefail

USER_CONFIRMED_DELETE="${USER_CONFIRMED_DELETE:-0}"

if [[ "$USER_CONFIRMED_DELETE" != "1" ]]; then
  echo "[REFUSE] USER_CONFIRMED_DELETE=0. 请 export USER_CONFIRMED_DELETE=1 后再 source 本文件."
  echo "[REFUSE] 同时请确认: 1) export_envs 已跑; 2) P0 已复制且 hash OK; 3) 夸克已上传."
  exit 1
fi
```

### A.2 rsync 失败排查

| 症状 | 可能原因 | 处理 |
|---|---|---|
| `rsync: mkdir "<dst>" failed: No such file` | 目标父目录未建 | 先跑 `create_quark_dirs.sh EXEC=1` |
| `rsync: send_files failed: No space left on device` | T 盘剩余 < 100 GB | 清 §D.1 (.cache 65 GB) 后重试 |
| `rsync: read errors mapping "<file>"` | 源文件被占用 (OneDrive 占位符) | 跑 §A.5 强制 make-available-offline |
| 大量 `*.pyc/__pycache__/wandb/` 被复制 | exclude 规则没传 | 检查 `"${EXCLUDES[@]}"` 是否带引号展开 |
| `rsync: symlink "<...>" -> "<...>" failed` | WSL 跨盘符号链接权限 | 加 `--copy-links` 或 `--safe-links` |
| `failed: Permission denied (13)` | Win 文件被占用 / WSL 无写 T 盘权限 | 关闭 Win 端打开该文件的程序, 或 `chmod -R +w` |

### A.3 hash mismatch 排查

```bash
# 症状: hash_check_*.tsv 里出现 MISMATCH 行
# 处理 1: 强制按 checksum 重传 (rsync 默认按 mtime+size, 改 --checksum 强校验)
rsync -avh --checksum "${EXCLUDES[@]}" "<src>" "<dst>"

# 处理 2: 单文件 md5 复检
md5sum "<src_file>"
md5sum "<dst_file>"

# 处理 3: 大文件 (>10 GB) md5 偶发出错, 用 sha256 双保险
sha256sum "<src_file>"
sha256sum "<dst_file>"

# 处理 4: 仍然 mismatch, 源文件可能损坏, 检查源文件 mtime 和大小
stat "<src_file>" "<dst_file>"
```

### A.4 夸克上传失败排查

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 上传卡在 99% 失败 | 单文件 > 100 GB | 拆分: ViBench 按 h5 分 16 片 (§B.4); WSL vhdx 不上传 (§D.5) |
| 上传速度极慢 (< 1 MB/s) | 夸克客户端限速 / 网络抖动 | 切换网络; 错峰凌晨上传; 重启夸克客户端 |
| 上传后夸克端文件大小为 0 | 客户端 Bug (上传中断但建了空文件) | 删夸克端空文件重传; 校验用 du -sb 对账 |
| 上传后夸克端 md5 不一致 | 客户端压缩 / 编码转换 | 夸克会对图片/PDF 做 CDN 优化, 二进制可能变; 用 zip 打包后再传避开 |
| 整个目录上传失败 | 夸克目录层级过深 (> 10 层) | 把深层目录 zip 成单文件再传 |
