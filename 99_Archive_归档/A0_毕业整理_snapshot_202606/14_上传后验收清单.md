## §A 验收三原则 (必须全部通过才算合格)

| # | 原则 | 含义 | 容差 | 通过条件 |
|---|---|---|---:|---|
| A1 | **文件数对账** | 夸克端文件数 == 本地总仓库端文件数 == manifest 行数 | 0 | 三方计数完全相等 |
| A2 | **字节大小对账** | 夸克端字节数 == 本地总仓库端字节数 == manifest `size_bytes` 之和 | 0 | 三方字节完全相等 (注意 rsync 不传 mtime, stat 用 `stat -c %s`) |
| A3 | **md5 内容对账** | 单文件 `src_md5 == dst_md5` (夸克端下载到本地校验 / 或夸克官方 md5 接口) | 0 | 全部行 `match=OK` (脚本输出 `_intermediate/logs/hash_check_*.tsv` 的 `match` 列无 `MISMATCH / MISSING_*`) |

**判定规则**:
- A1 + A2 + A3 三项全部 OK ⇒ 该批次验收通过, 可以继续下一批.
- 任一 FAIL ⇒ 立即停止后续上传, 定位失败行 (差异文件 / 差异字节 / 差异 md5), 重传或补传.
- A3 单文件 MISMATCH 通常意味着上传过程被中断或夸克做了转码; 博士论文 PDF / 答辩录像 / h5 这类大文件是高风险点.

**为何容差为 0**:
- 夸克是企业级网盘, 文件级完整性是商业合同底线, 不存在"近似上传".
- 博士论文 / ViBench 数据 / Zotero 索引均为不可再生 S 级资产, 一字节错位即不可用.
- 三方全等才能确保即使夸克侧损坏, 也有完整本地副本可重传.

### B.5 三方对比脚本 (verify_batch 函数)

```bash
# 把下面这段贴到 _intermediate/logs/verify.sh, 然后 source 它
# 用法: verify_batch B01
verify_batch() {
  local B="$1"
  local CSV=/mnt/t/A0_毕业整理_v2/manifests/upload_manifest.csv
  local DST_ROOT="/mnt/t/博士毕业数据总仓库_202606"

  echo "===== Batch $B 三方校验 ====="

  # 期望: manifest 行数 + 字节之和
  read MANIFEST_ROWS MANIFEST_BYTES < <(python3 -c "
import csv,sys
b=sys.argv[1]; n=s=0
with open('$CSV',encoding='utf-8') as f:
    for r in csv.DictReader(f):
        if r['batch_id']==b: n+=1; s+=int(r['size_bytes'])
print(n,s)
" "$B")
  printf "manifest 行数 = %s, 字节 = %.3f GB\n" "$MANIFEST_ROWS" \
    "$(python3 -c "print($MANIFEST_BYTES/1024**3)")"

  # 本地总仓库端: 文件数 + 字节
  local DST_FILES=$(find "$DST_ROOT" -type f 2>/dev/null | wc -l)
  local DST_BYTES=$(du -sb "$DST_ROOT" 2>/dev/null | awk '{print $1}')
  printf "本地总仓库 文件 = %s, 字节 = %.3f GB\n" "$DST_FILES" \
    "$(python3 -c "print($DST_BYTES/1024**3)")"

  # md5 校验 (P0 用 scripts/hash_check.sh, 全量用下方扩展)
  bash /mnt/t/A0_毕业整理_v2/scripts/hash_check.sh \
    /mnt/t/A0_毕业整理_v2 "$DST_ROOT"

  # 判定
  if [[ "$MANIFEST_ROWS" == "$DST_FILES" && "$MANIFEST_BYTES" == "$DST_BYTES" ]]; then
    echo "[A1+A2 PASS] 文件数+字节一致"
  else
    echo "[A1/A2 FAIL] 需排查"
  fi
}
```

## §F 失败处理流程 (任一 ☐ 未打勾)

1. **A1 文件数不一致**:
   - 多: 可能有临时文件混入 (`.tmp` / `.DS_Store` / `Thumbs.db`), 用 `find ... -name ".DS_Store" -delete` 人工确认后清理 (rm -i 模式).
   - 少: 漏传, 重跑 §B.6 rsync dry-run 找出差异文件补传.

2. **A2 字节不一致**:
   - 通常伴随 A1, 优先排查文件数.
   - 若文件数一致但字节不一致, 检查是否有同名不同内容 (rsync `-I` 忽略时间戳强制覆盖).

3. **A3 md5 MISMATCH**:
   - 单文件: 删 dst 后 rsync 重传 (rm -i 模式, 不动 src).
   - 多文件批量失败: 检查网络/磁盘是否在传输中损坏, 重跑全量 hash_check.

4. **§D 敏感泄漏**:
   - **立即在夸克客户端删除该文件** (人工操作, 不在本仓库脚本范围).
   - 排查泄漏来源: 通常是 rsync 排除规则漏写, 检查 `scripts/copy_p0_execute.sh` 的 `--exclude` 列表.
   - 全量重扫 §D.1 + §D.2, 直到返回空.

5. **§E 总清单任一未通过**:
   - 在 `_intermediate/logs/final_acceptance_YYYYMMDD.md` 记录未通过项 + 排查过程 + 修复时间.
   - 不允许"部分通过即结项", §E 15 条全部 ☑ 才算完成.
