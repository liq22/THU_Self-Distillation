# LQQL_OS 自蒸馏 OS 方法论

> 来源：博士毕业源仓库 os_cards/018_LQQL_OS自蒸馏OS.md（9.2 GB 全仓提炼）
> 整理日期：2026-07-09
> 适用范围：博士 5 年沉淀的"Obsidian Life OS + Agent Skills + Spec-Driven 论文流水线"三位一体个人知识管理方法论

## 边界说明

这页是**方法论提炼**，不是全仓索引、不是资产清单。

- 是什么：把 LQQL_OS 这个"自蒸馏 OS"可复用的**结构 + 原则 + 闭环**抽出来，写成可以迁移到博后、写书、指导学生的方法论。
- 不是什么：不是目录树转写、不是 9.2 GB 资产的内容搬运、不是 canonical skills 清单（那是 [[canonical_skills注册表方法论]] 的事）。大体积资产（9.2 GB 全仓 / 5 GB venv / 163 MB git）和论文全文只写私有指针，不内联。

## 适合谁读

如果你想给博士 / 博后期间散落在多个仓库、多个工具里的笔记、代码、论文、agent 规则建一套**能复用、能被 agent 读懂、能跨平台迁移**的主版本——这页是给你看的三位一体方法论总纲。特别适合清华机械系或相关方向、即将从博士过渡到博后的研究者。

## 读完能做什么

- 拿到"Obsidian Life OS + Agent Skills + Spec-Driven 论文流水线"三位一体方法论的结构骨架，知道哪一页讲什么、彼此怎么缝。
- 照着"对象分层 + 五层流水线 + 任务后学习闭环"的可执行清单，给自己仓库搭出第一版主结构。
- 识别"分主题当顶层 / raw 被改写 / 大资产进 git / 任务后学习流于形式"这几类最容易卡住的地方，提前规避。

## 场景

博士 5 年间，笔记、代码、论文、项目、agent 规则、模板散落在多个仓库和多个工具里。到毕业整理时需要一套**能被复用、能被 agent 读懂、能跨平台迁移**的主版本，而不是一堆临时目录。LQQL_OS 就是把所有这些沉淀进一个 Obsidian + git 仓库，并用一套统一的"对象分层 + 编号 + skill 注册表 + 论文流水线"把主版本固定下来。

## 当时的问题

整理过程中反复出现几类痛点，这套方法论是对它们的回答：

1. **目录按主题分还是按对象分**：纯按主题分会把"待办、归档、agent 用"混进同一棵知识树，难维护。
2. **raw 被反复改写**：原始记录一旦被 agent 或人工改写，溯源链就断了。
3. **大文件把仓库撑爆**：视频、数据集、venv、PDF 全文塞进 git，仓库不可用。
4. **agent 高风险操作**：没有 write_policy / fix 机制时，agent 会误删或覆盖。
5. **学不到东西**：任务做完就结束，不沉淀成 skill，下次还从零开始。

## 为什么会发生

前 4 个问题是"没有先分层、没有保护机制"导致的结构债；第 5 个是"缺少任务后学习闭环"导致的经验流失。根因是：知识系统需要同时承担**内容存储、agent 协作、论文生产**三件事，而这三个诉求对结构的要求是冲突的——内容要全、协作要稳、生产要快。LQQL_OS 的回答是：把三者拆到不同的"平面"和不同的"流水线层"，用统一编号把它们缝起来。

## 后来怎么解决

核心是**三位一体**：Obsidian Life OS（结构）+ Agent Skills（协作）+ Spec-Driven 论文流水线（生产），靠"对象分层 + 编号"做总骨架。

### 1. 对象分层 + 编号（总骨架）

先分对象，再分主题。顶层用编号分区，每个分区是一类"对象"，而不是一类"主题"：

- `00_系统说明/` — 原则 + 命名 + 模板中心（元层）
- `01_灵感或待办/` — 收件箱 + 日记 + 剪藏（输入面）
- `02_战略与规划/` — 北极星 + 5/10 年 + 年度重点 + 反目标
- `03_家庭与人脉/` — 关系网络
- `04_生活与娱乐/` — 生活运营
- `05_知识与技能/` — 12 个主题（元知识/职业AI/金融/沟通/认知/审美/数字基建/智能体开发/工科/文学/讲座/模板）
- `06_工作与项目/` — 5 个真实执行单元（自动研究引擎 / 论文流水线 / GPTPro / 人生智慧迁移 / 博士毕业流程）
- `07_给智能体用/` — agent 协作规则 9 份
- `99_归档/` — 冷存储

规则：**项目是 data plane，OS 是 control plane**——执行单元（06_）落 data plane，规则与模板（00_/07_/配置层）落 control plane。详细的治理观见 [[对象分层与控制平面]]。

### 2. 五层处理流水线（raw → dashboard）

任何输入从"原始"走到"可用"都经过固定五层：

1. **raw** — 原始记录，**不改写**（保溯源）。
2. **compiled** — 整理后产物。
3. **schema** — 结构化字段（让 agent 可解析）。
4. **skill** — 固化成可复用能力（最小完整包：SKILL.md + examples/prompts.md）。
5. **dashboard** — 面向人的总览与待办。

关键约束：raw 只追加不覆盖；只有走到 skill 层才算"学会了"。

### 3. 渐进式读取协议

agent 进仓库不一次性扫全树，而是按固定顺序逐层打开：

> README → INDEX → 必要文件 → LOG

目的是控制上下文成本、避免一次性吃进 9.2 GB 的噪音。

### 4. fix 机制 + 高风险保护

对高风险目录用写策略保护：

- `write_policy: readonly` — 只读
- `scope: subtree` — 限定子树
- `fix` 机制 — 命中风险时降级到 hold / recommendation，不直接改

这条对应全局规则里的"raw、fix、readonly、高风险或高歧义场景降级"。

### 5. 任务后学习闭环

每个任务做完后判断是否产生可复用 lesson，命中就回写到 canonical skill（`@post-task-learn`）。不默认在交付后立即结束，而是先问"这次有没有高信号经验"。这条把"一次性任务"变成"长期资产积累"。

### 6. Spec-Driven 论文流水线

论文写作用 `.specify/` + `goal/codex_goal_*` 的 spec-driven 流程：先写规格（goal），再由 agent 按规格生成，而不是直接写正文。详细工作流见 [[spec_driven论文写作工作流]]。

## 抽象原则

- **先分对象再分主题**：对象（待办/战略/项目/agent/归档）决定顶层结构，主题只在叶子层出现。
- **raw 不改写**：保住溯源链是一切整理的前提。
- **OS 是 control plane，项目 repo 是 data plane**：规则模板与执行内容分离。
- **五层流水线统一所有输入**：raw → compiled → schema → skill → dashboard，只有走到 skill 才算学会。
- **高风险目录强制降级**：readonly / scope / fix 三件套保护不可再生资产。
- **任务后学习是默认动作，不是可选**：每个任务结束先问"有没有 lesson"。
- **大资产只写指针**：视频/数据集/venv/PDF 全文绝不内联进 git。

## 可执行清单

- [ ] 新建仓库时，顶层先按"对象"分（00 系统 / 01 待办 / 05 知识 / 06 项目 / 07 agent / 99 归档），再在每个对象内分主题。
- [ ] 所有原始记录落 raw 层并标注"只追加不覆盖"。
- [ ] 在仓库根放 README → INDEX → 必要文件 → LOG 四件套，作为 agent 渐进式读取入口。
- [ ] 对 raw / 敏感 / 归档目录配置 `write_policy: readonly` 与 `scope: subtree`。
- [ ] 每个任务收尾前过一遍 `@post-task-learn`：有 lesson 就回写 canonical skill，没有就放行。
- [ ] 大资产（>几十 MB 的视频/数据集/venv/PDF）只写路径指针，不进 git。
- [ ] 论文用 spec-driven：先 `.specify/` 写 goal，再让 agent 按规格生成。

## 适用边界

- 本方法论是从**单人多平台、博士到博后过渡期**沉淀出来的；团队协作场景需要额外补权限与 review 层，本页不覆盖。
- "五层流水线"是默认骨架，不是硬性五步——材料稀薄时允许合并 raw→compiled，但不能跳过 raw。
- skill 注册表的**具体清单**与维护规则见 [[canonical_skills注册表方法论]]，本页只讲方法论层面。
- 论文流水线的**具体 spec 模板与命令**见 [[spec_driven论文写作工作流]]，本页只讲它如何嵌进 OS。

## 最容易卡住的地方

1. **把"分主题"当成顶层组织方式**：最容易犯的错。一旦顶层按主题分，待办和归档就会污染知识树。先按对象分，主题留到叶子。
2. **raw 被顺手改写**：agent 或人在整理时直接改 raw，溯源链立刻断。raw 层必须配 readonly。
3. **大资产偷偷进 git**：venv、数据集、PDF 全文是仓库体积爆炸的主因。默认只写指针。
4. **任务后学习流于形式**：每次都回写会变成空壳 skill。要有"高信号才写"的判断，源太薄就降级为 hold。
5. **把 OS 当 data plane 用**：执行内容塞进 00_/07_，control plane 被污染。执行单元必须落 06_ 这类 data plane。
