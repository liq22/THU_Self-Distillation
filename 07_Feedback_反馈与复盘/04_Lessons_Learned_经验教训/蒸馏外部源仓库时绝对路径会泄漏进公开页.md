# 蒸馏外部源仓库时，绝对机器路径会泄漏进公开页

## 场景

把 `D:\A0_博士毕业数据总仓库_202606\A0_毕业整理\` 的 14 张 OS 卡片深度蒸馏进本 vault（14 张卡 → 31 个知识页 + 仪表盘回填）。源卡片里大量用绝对 WSL 路径定位资产（`/mnt/k/2_work/LQQL_OS/...`、`/mnt/d/paper/thesis/`、`/home/<user>/...`）。

## 当时的问题

蒸馏完成后验证发现：10 个公开蒸馏页（ViBench closeout、R00 代码结构、PHM-Vibench 数据集索引、神经符号综述、closeout、CV 维护等）原样抄进了源卡片的 `/mnt/...` 与 `/home/<user>/...` 绝对路径，其中 4 页还是 `visibility: public`。学号 / token / 邮箱 / 电话等强敏感项 0 命中（脱敏到位），但**机器路径 + 用户名 `<user>` / `<user>` 漏了**——尽管 prompt 里明确要求"大体积/敏感资产只写路径指针进 98_Private"。

## 为什么会发生

- 蒸馏 agent 把"资产位置指针"理解成**直接抄源路径**，而非"记到私有指针区、公开页只留相对引用"。prompt 里"路径指针"措辞有歧义（既可指公开页里的路径，也可指私有区指针文件）。
- 路径不像学号那样触发"敏感"直觉，agent 默认它是中性的"在哪找资产"信息，没主动脱敏。
- 现有 vault 风格（如 [[毕业流程操作指南]]）其实**避免**绝对路径、只用相对文件夹结构，但 agent 没拿这个当硬约束。

## 后来怎么解决

1. 先 grep 出所有 `/mnt/[a-z]/`、`/home/<user>/` 命中与去重前缀。
2. 建 `98_Private_LOCAL_勿提交/资产指针索引_2026-07-09.md`（gitignored），把完整绝对路径 + 资产说明 + sha256 来源集中到私有区。
3. 对 10 个公开页跑 sed：长前缀（`/mnt/k/2_work/LQQL_OS/lqql_06_工作与项目/03_论文流水线/` → `LQQL_OS/论文流水线/`、`/mnt/k/D01_vibench/` → `D01_vibench/`、`/home/<user>/` → `~/`）替换成**可移植相对 token**，保留有意义的尾部，去掉盘符/用户名/冗余前缀。具体→规则见特定→兜底（specific-first sed）。
4. 复验：公开蒸馏树 `/mnt` 与 `<user>` 命中归零。

## 抽象原则

- **"路径指针"要拆成两半**：公开页只留**相对/可移植 token**（`LQQL_OS/论文流水线/X/`），完整**绝对机器路径**只进 gitignored 的私有指针索引。不要让绝对路径进公开 git 树。
- **蒸馏 agent 会原样抄源里的路径与用户名**，即便要求脱敏——路径/用户名不像学号触发敏感直觉。必须靠**验证 grep 兜底**，不能只靠 prompt。
- **忠实证据快照 ≠ 蒸馏页**：快照（99_Archive）忠实保留源（含源里的学号/路径），是另一套规则；蒸馏页要按 vault 风格去绝对路径。快照若进公开仓，其学号也要单独 sed 脱敏（本次 22 文件 `<学号_redacted>` → `<学号_redacted>`）。
- **源不变性要基线 + 终检双测**：开工前 `find -type f | wc -l` + `du -sb` 记基线，收尾重测逐字节比对，才能证明 COPY-ONLY 没误写源。

## 可执行清单

- [ ] 蒸馏前：`find <src> -type f|wc -l` + `du -sb <src>` 记源基线。
- [ ] 蒸馏后必跑两条 grep：①强敏感值（学号/身份证/手机/邮箱/token 形态 sk-/ghp_/AKIA/Bearer）；②机器路径与用户名（`/mnt/[a-z]/`、`/home/<user>/`、Windows 盘符）。
- [ ] 命中机器路径：建/更新 `98_Private_LOCAL_勿提交/资产指针索引_<date>.md`，公开页 sed 成相对 token（specific-first），保留尾部去前缀。
- [ ] 快照进公开仓前：单独 grep 学号并 sed 脱敏，README 注明"文件名引用中学号已脱敏，内容忠实"。
- [ ] 收尾：重测源 `find/du` == 基线，证源未改。
- [ ] 把 ingest 工作流（`11_Skills/phd-self-os/workflows/01_ingest_and_link`）补一条"产出页不得含绝对机器路径"硬规则。
- [ ] **规则/meta 文件也查**：写"脱敏规范""复盘 lesson"时若把敏感 token 当例子引用（`2022xxxxxxx` 学号、`richie_thu` 用户名、`/mnt/k/...` 路径），例子本身也会泄漏真值——必须用占位符（`<学号_redacted>` / `<user>` / `/home/<user>/` / 盘符用 `<drive>`），规则文件不是法外之地。本次任务把学号/用户名从 2 个处理规范 + 本 lesson 里 sed 复清。

## 适用边界

- 适用：任何把外部源仓库（含绝对路径、用户名、机器布局）蒸馏/导入进 Obsidian 公开 vault 的任务。
- 不适用：纯内部私有区（98_Private）的原件归档——那里保留绝对路径是合理的。
- **父级 `lqql_05_知识与技能/09_智能体开发` 是更通用的方法论承载页**，但其在 `fix:true / readonly / subtree` 围栏内，本次未写入；如需把本课上提到 OS 级方法论，需用户显式授权越过围栏。
